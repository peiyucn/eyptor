# TOC 两态模型（去掉钉住 / 整体收展 / 悬浮）

> 状态：已实现（v1.2.0，2026-09-13）｜需求来源：手测反馈「toc 自适应出现维持不住」「整体收起展开没用了」「钉住是不是也可以不要」，参照 **DSH 左边栏**的实际行为（用户在 DSH 上实测确认）

## 状态

只有两个：**打开** / **关闭**。没有钉住态、没有悬浮态、没有整体收起/展开按钮。

## 优先级（这是本 spec 的核心 —— 用户在 DSH 上逐条实测确认）

| 事件 | 结果 |
|---|---|
| **用户点击关闭** | **最高优先级**，并持久化：此后**无论宽度怎么变都不再自动打开**，只有用户再次点击打开才解除 |
| **用户点击打开** | 解除上面的关闭偏好；**是否保持由宽度决定**——空白够就保持，不够就被自动收起（手动打开**不**能压过宽度规则） |
| **宽度变化** | 仅在**没有**关闭偏好时起作用：空白 ≥ 阈值 → 打开；< 阈值 → 收起 |

一句话：**只有"用户关掉"是黏性的，"用户打开"是临时的。**

## 版面

* 打开 = 常驻 + **推正文**（不遮字；空白放不下也推，不再有"悬浮/放不下就推开"的条件分支）；
* 关闭 = 只留左侧一根把手；
* 把手图标 = 方向箭头，随状态翻转：展开态 `←`、收起态 `→`（tooltip：收起目录 / 展开目录）；
* 持久化字段：`tocDismissed`（新增，承载"关闭偏好"）、`tocWidth`、`tocCollapsed`；**删除 `tocPinned`**。

## 删除项（连同其代码与图标一起清）

* 图钉按钮与 `isPinned` 状态、`toc-pinned` body class 的"钉住"语义；
* 整体收起 / 展开按钮（每个节点自己能收展，它多余）；
* `isAutoShown` 这个布尔量与"自动/手动"两条 `openPanel(auto)` 分支（被上面的优先级表取代）。

## 文案

标题由 `Table of Contents` 改为 `Contents`（中文仍为「目录」）。

## 宽度阈值（补记，2026-09-12 手测反馈）

反馈：「自动展开关闭的宽度值，有点大」。根因是上一版判据 `freeLeftMargin() = (视口宽 − 正文列宽) / 2`
**把面板自身的影响算了进去**：打开态推正文 → 正文被推窄 → 该公式算出的"空白"同步缩水 →
"一打开就判定放不下"，等效把阈值放大了一个面板宽度。这是反馈回路，不是数值没调好。

实现要求：
* 阈值必须基于**不受面板影响的量**（窗口可用宽，或"扣掉面板自身 padding 后"的正文列宽）；
* 数值**跟着用户设置的编辑页宽度走**：`阈值 = epytor.editorMaxWidth + 100`
  （默认 900 → **1000px**；用户把编辑页宽度改大改小，阈值动态跟着 ±，不写死）；
* 不用"面板宽度 × 比例"这类随面板拖宽而变的表达。

## 验收标准

1. 点击关闭后，窗口从很宽拖到很窄再拖回很宽，TOC 都不再自动出现；
2. 点击打开后，把窗口拖窄到空白不足 → 自动收起（手动打开不压过宽度规则）；
3. 未点过关闭时，宽度够即自动出现、不够即自动收起；
4. 打开态始终推正文、不遮挡文字；
5. 把手箭头方向与状态一致；
6. 界面上不再有图钉与整体收起/展开按钮；标题显示 `Contents`。
