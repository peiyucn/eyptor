# Spec：FindBar 正则搜索

> 创建日期：2026-09-04
> 状态：实施中
> 归属：v1.2 批次二（借鉴 git-xing/md-wysiwyg-editor v0.3.0 FindBar 正则能力）

## 需求范围

在现有编辑器内查找栏（`webview/components/findBar`）上新增「正则表达式」开关，与现有「区分大小写」开关并列：

- 关闭：现有逐字匹配行为（不变）
- 开启：查询串按 JavaScript 正则解析（`RegExp`），大小写开关控制 `i` flag

## 交互边界

- 按钮位置：`Aa`（大小写）按钮之后、关闭按钮之前；label `.*`，激活态样式与 `Aa` 一致（`find-bar__btn--active` + `aria-pressed`）
- 实时搜索：输入防抖 150ms 不变，开关切换立即重新搜索
- **无效正则**：输入无法解析的正则（如 `(`）时，不崩溃——计数区显示「Invalid Regex」文案 + 输入框错误态样式（红边），清空全部高亮；修正后自动恢复
- **零宽匹配防护**：正则可能匹配空串（如 `.*`、`a*`），必须防止 exec 死循环（空匹配时手动推进 lastIndex）
- 高亮/导航：沿用 CSS Custom Highlight API 与 Enter/Shift+Enter 导航，无变化
- 范围：与现有搜索一致，限定在编辑器容器内文本节点，不影响代码块预览（TreeWalker 遍历的是 editor DOM）

## 验收标准

- [ ] 正则模式匹配多结果并正确计数（如 `\d+` 匹配所有数字）
- [ ] 大小写开关在正则模式下正确控制 `i` flag（`foo` vs `FOO`）
- [ ] 无效正则显示错误文案且编辑器无异常，修正后恢复匹配
- [ ] 零宽正则（`.*`）不卡死，输入 1000+ 行文档时搜索即时返回
- [ ] 普通模式行为零回归（原有测试 + 手测）
- [ ] 纯匹配逻辑提取为独立模块并补单元测试（普通/大小写/正则/无效/零宽各至少一例）
