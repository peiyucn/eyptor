## 0. 用户反馈的两个严重问题（本轮根因修复，优先验证）

* [ ] **开着 md 页面时，VS Code 整体输入不再卡顿**——编辑含代码块的 md 文档，中文输入连续打字 30 秒，观察是否还有偶发卡顿（回归：CodeMirror 主题补配观察器 10ms 一次无限回环，持续烧 CPU）
* [ ] **开着 md 页面时，在 DSH 页面切换会话不再带着整个 VS Code 闪动**——保持一个含代码块的 md 标签打开，切到浏览器里的 DSH 页面连续切换会话，观察 VS Code 窗口是否还闪
* [ ] 可选客观验证：命令面板 → `Developer: Open Process Explorer`，观察 epytor webview 进程的 CPU 占用是否稳定在低位（此前会持续占用一个核心的一部分）
* [ ] 主题切换（亮/暗）后代码块高亮跟随，且切换后新插入的代码块高亮也是当前主题

## 2. 图片路径往返（P8 + E7）

* [ ] 图片右键/工具栏「编辑路径」输入相对路径 → 确认后图片正常显示（走 Extension 解析）
* [ ] 图片路径补全（输入 `./` 触发下拉）→ 选中后确认，图片正常显示
* [ ] 图片重命名后（工具栏重命名），再次编辑该图片路径并确认，仍指向正确文件（回归：反向镜像陈旧）
* [ ] **路径含括号/空格的图片**（如 `images/my (v2).png`）：打开 → 编辑一次正文 → 保存 → 用文本编辑器查看源码，src 仍是相对路径（**回归：此前序列化会把括号转义成 `\(`，保存时匹配不上 → webviewUri 泄漏进磁盘文件**）
* [ ] 代码块里写一行裸 `vscode-webview://...` 或含图片语法的文本 → 保存后该代码块内容不被改写（回归 E7）
* [ ] 图片 title（如 `![alt](./a.png "ratio:0.5")`）在编辑路径后仍保留
